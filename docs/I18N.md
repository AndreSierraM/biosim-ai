# i18n workflow (Crowdin-compatible)

The web UI ships two locales: Spanish (default) and English.

- Source of truth: `apps/web/src/i18n/en.json` (English, Crowdin source).
- `apps/web/src/i18n/es.json` is the in-repo default locale.
- `apps/web/src/i18n/index.tsx` enforces compile-time key parity
  (`const _parity: Strings = en`) — a missing key fails `npm run build`.
- The `LocaleSwitcher` persists to `localStorage` (`biosim-locale`) and
  syncs `<html lang>` + `document.title`.

## Translating via Crowdin

1. Create a Crowdin project, add the repo integration with `crowdin.yml`.
2. Upload `en.json` as source; translators produce `%locale%.json`.
3. Download translations back into `apps/web/src/i18n/`.
4. `cd apps/web && npm run build` must stay green (parity is type-checked).

Server-side strings (planner refusals, assay assumptions, API errors)
stay in their source language for now; the UI never invents translations
for measured values or engine output.
